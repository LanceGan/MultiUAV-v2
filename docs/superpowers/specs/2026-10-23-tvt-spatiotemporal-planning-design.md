# 面向 IEEE TVT 的多无人机通信感知巡检方法重设计

> 日期：2026-10-23
> 状态：设计稿，待用户批准后再编写实施计划
> 目标期刊：IEEE Transactions on Vehicular Technology（TVT）
> 暂定方法名：STC-ALNS（Spatio-Temporal Conflict-Aware Adaptive Large Neighborhood Search）

## 1. 设计意图

本文研究多架蜂窝联网无人机在乡村宏蜂窝环境中协同执行巡检任务的问题。每个巡检点在被访问后立即产生数据，无人机在飞往下一巡检点的过程中通过 A2G 上行链路上传该数据；在进入下一巡检点的到达区域之前，上一巡检点的数据必须上传完成。多架无人机共享蜂窝扇区带宽，因此某条航段的真实通信代价不仅取决于自身轨迹，还取决于其他无人机在相同时刻经过的扇区、缓存状态和带宽竞争情况。

旧设计把单段 TD3 作为核心方法，但现有公平门控结果表明 TD3 同时弱于 Straight-Hold 和简单 Comm-Waypoint。新设计不再预设 DRL 必须获胜，而将论文核心改为：

1. 建立可显式描述航段时间、扇区占用和缓存状态的候选航段库；
2. 建立逐时隙、只对活动上传者分配带宽的同步多无人机评价器；
3. 建立利用具体“边—时间—扇区”冲突信息进行破坏、修复和时移的自适应大邻域搜索；
4. 在同一物理模型和可行性口径下，与轨迹优化、路线搜索和资源无感知方法进行公平比较。

本文不以“使用强化学习”本身作为创新。TD3/DDPG/SAC 作为轨迹层基线保留；若后续学习策略能够以明显较低的在线计算代价逼近优化航段，可作为加速型代理模型，而不是论文成立的前提。

## 2. 研究问题与论文定位

### 2.1 核心研究问题

给定无人机、巡检点、数据量、蜂窝扇区地图和共享带宽规则，联合决定：

- 每个巡检点由哪架无人机访问；
- 每架无人机的巡检顺序；
- 相邻巡检点之间选择哪条通信可行航段；
- 各无人机的起飞时移；

使系统任务完成时间和数据上传时延的加权归一化目标最小，并满足任务唯一访问、数据完整上传和下行中断约束。

### 2.2 TVT 论文主线

论文主线不是“DRL 比直线飞行更好”，而是：

> 静态、可加的单机边权无法表示多无人机共享频谱导致的时空非可加代价。本文通过保留候选航段的时间—扇区—通信剖面，构造同步评价器和冲突感知 STC-ALNS，在任务分配、访问顺序、航段选择和起飞时移之间进行分层联合优化。

### 2.3 预期贡献

1. **时空扇区冲突模型**：定义由活动缓存、扇区关联和时间重叠共同产生的非可加航段冲突，并说明传统独立边权为何不能准确评价共享带宽系统。
2. **多候选通信可行航段库**：为每条有向边保留飞行时间、上传时延、G2A 可靠性和扇区占用互有差异的 Pareto 候选，而非只保留单一最短或单一 DRL 航段。
3. **STC-ALNS**：利用冲突热点、关键路线和边际拥塞代价设计自适应 destroy/repair、航段切换和起飞时移算子，并通过增量同步评价引导搜索。
4. **严格证据链**：在统一评价器下进行小规模最优性差距、强基线、机制消融、多随机种子、规模和鲁棒性实验。

## 3. 目标、非目标与失败条件

### 3.1 目标

- 形成一个物理语义一致、可复现的多无人机通信感知巡检仿真系统；
- 证明共享带宽使路线代价具有时间耦合和非可加性；
- 证明 STC-ALNS 相对资源无感知路线搜索能够稳定改善端到端目标或可行率；
- 在小规模问题上报告相对精确离散求解的最优性差距；
- 在中等规模问题上报告性能、稳定性和计算开销。

### 3.2 本文明确不做

- 不把端到端 MARL 作为主方法；
- 不宣称获得连续空间全局最优轨迹；
- 不宣称固定地图训练的 TD3 具有跨地图通用泛化能力；
- 不在主问题中联合优化发射功率；发射功率作为外生参数进行敏感性分析；
- 不处理在线新增巡检点或动态任务到达；
- 不把尚未实现的精细旋翼能耗、安全投影或实机验证写成已完成贡献。

### 3.3 反目标

即使代码能够运行，出现以下任一情况也不能作为论文完成：

- 各方法使用不同上传完成、悬停或失败定义；
- 只比较各方法各自的成功子集；
- 新方法只优于直线飞行而不优于通信感知强基线；
- 把平均拥塞系数近似称为精确闭环；
- 把同时改变区域、点数和基站数的结果解释为纯 UAV 数量扩展；
- 从单地图或单随机种子结果得出稳健性结论；
- 正式结果无法由冻结的代码、配置、地图和命令独立复现。

## 4. 方案选择

### 4.1 方案 A：轨迹优化 + 时空冲突感知路线搜索（选定）

Comm-Waypoint、网格图搜索和 SLSQP 负责生成候选航段；STC-ALNS 联合选择任务、顺序、航段候选和起飞时移。优点是可解释、可复现、容易与精确小规模解比较，且已有 Comm-Waypoint 门控结果支持继续发展。

### 4.2 方案 B：重新设计 TD3（不作为主线）

增加局部速率、outage、扇区负载、带宽和功率等观测，并通过多地图域随机化训练。风险是训练成本高，且即使性能提升，也未必优于直接优化。仅允许作为有明确时间预算和停止门槛的旁支。

### 4.3 方案 C：完全取消轨迹层（不选）

仅优化任务分配、顺序和调度。实现最简单，但容易退化为常规车辆路径启发式加通信后处理，难以形成足够集中的 TVT 方法贡献。

## 5. 系统模型

### 5.1 集合和参数

- 无人机集合：\(\mathcal U=\{1,\ldots,U\}\)；
- 巡检点集合：\(\mathcal K=\{1,\ldots,K\}\)；
- 蜂窝扇区集合：\(\mathcal M=\{1,\ldots,M\}\)；
- 离散时隙：\(n=0,1,\ldots,N\)，时隙长度为 \(\Delta t\)；
- 巡检点 \(k\) 的坐标和数据量：\(\mathbf w_k\)、\(I_k\)；
- 无人机 \(u\) 的起点和终点：\(\mathbf q_u^{\mathrm s}\)、\(\mathbf q_u^{\mathrm e}\)；
- 扇区带宽：\(B_m\)；固定 UAV 上行发射功率：\(P^{\mathrm{UL}}\)；
- 到达半径：\(r_{\mathrm{arr}}\)；路线级中断阈值：\(\epsilon_{\mathrm{out}}\)。
- 任务截止时间：\(T_{\max}\)；单航段最大等待时间：\(W_{\max}\)；
- 起飞时移集合：\(\mathcal D=\{0,\Delta_\delta,\ldots,\delta_{\max}\}\)。

所有正式计算统一采用 SI 单位。现有 100 m、km、Mbit、MHz 接口必须在输入适配层完成转换，不能在核心评价器内部混用。

主论文采用固定高度二维运动模型。候选路径由分段直线组成，飞行段采用 \(v_{\max}\)，等待段速度为零；不在主问题中加入加速度、最小转弯半径或三维高度决策。所有候选必须位于区域边界内。这样路径代价来自几何路径、通信条件和等待，而不是尚未实现的飞控细节。

### 5.2 任务和数据语义

每个巡检点使用固定服务锚点 \(\mathbf w_k\)。无人机进入以 \(\mathbf w_k\) 为中心、半径 \(r_{\mathrm{arr}}\) 的数值终止区域，并完成候选路径规定的最后连接段后，才触发一次巡检事件并获得 \(I_k\) bit 数据。所有入边和出边都以同一个服务锚点为拼接状态，避免把独立航段从不同的到达圆边界位置直接拼接。该数据必须在触发下一巡检事件前上传完成；最后一个巡检点的数据必须在触发终点完成事件前上传完成。

若无人机已经接近下一巡检点但缓存仍非空，则停留在到达边界之外、由该航段候选显式给出的合法等待位置，继续上传；缓存清空后再完成最后连接段。禁止先触发巡检再在目标点内补传上一数据包。若单航段等待超过 \(W_{\max}\)，或系统完成时间超过 \(T_{\max}\)，该解判为不可行，不能通过无限等待获得可行性。

### 5.3 无线地图

离线地图为每个位置和扇区分别提供：

- A2G 上行频谱效率 \(\eta_m^{\mathrm A}(\mathbf q)\)；
- G2A 下行中断概率 \(p_m^{\mathrm G}(\mathbf q)\)。

规划阶段使用固定地图上的统计平均值；鲁棒性测试使用独立快衰落样本或独立地图。地图必须显式接收 `map_seed`，并与训练、任务和搜索 seed 分离。

### 5.4 航段候选

对有向边 \(e=(i,j)\)，构造候选集合 \(\mathcal L_e\)。候选 \(\ell\in\mathcal L_e\) 保存：

\[
\mathcal P_{e\ell}=\left\{
\mathbf q_{e\ell}[h],
\eta_{e\ell,m}[h],
p_{e\ell,m}^{\mathrm G}[h],
m_{e\ell}^{\star}[h]
\right\}_{h=0}^{H_{e\ell}}.
\]

其中 \(\mathbf q_{e\ell}[h]\) 为离散轨迹，\(m_{e\ell}^{\star}[h]\) 为无负载条件下的首选扇区。每个候选还保存：

- 独占带宽下的飞行时间 \(T_{e\ell}^{0}\)；
- 独占带宽下的上传完成时延 \(D_{e\ell}^{0}\)；
- 累计和最大连续 G2A 中断指标；
- 是否满足动力学、边界和独占带宽上传约束；
- 时间—扇区占用签名。

候选来源至少包含：

1. Straight-MaxSpeed，仅作松弛参考；
2. Straight-Hold，在到达区外补传的合法可行基线；
3. Comm-Waypoint，自适应选择高频谱效率中继点；
4. Grid A*/Dijkstra，在离散通信代价图上搜索；
5. Waypoint-SLSQP，对最优离散候选进行连续精化；
6. TD3/DDPG/SAC，仅作为学习型比较方法。

对每条边只保留在 \((T^0,D^0,O,\text{sector signature})\) 上非支配且具有扇区多样性的候选。不能只按单机目标保留一个最优候选，否则外层无法通过替换航段避免多机冲突。

### 5.5 同步带宽与缓存模型

定义 \(Q_u[n]\) 为无人机 \(u\) 在时隙 \(n\) 开始时的缓存，\(b_u^{\mathrm{air}}[n]\) 表示无人机已经起飞且尚未完成任务。每个空中无人机在每个时隙关联一个同时服务上下行的扇区：

\[
\sum_m a_{u,m}[n]=b_u^{\mathrm{air}}[n].
\]

有缓存的无人机优先从满足预设 G2A 可靠性条件的扇区中选择 A2G 频谱效率最大的扇区；若没有满足条件的扇区，则选择 G2A 中断概率最小的扇区并在路线可靠性中累计违规。无缓存无人机选择 G2A 中断概率最小的扇区，但不占用上行带宽。

只有满足以下条件的无人机才是活动上传者：

\[
\chi_u[n]=\mathbb I\{Q_u[n]>0\ \land\ u\text{处于任务执行期}\}.
\]

第一版主模型采用上述可靠性优先关联和同扇区活动上传者等带宽分配：

\[
N_m[n]=\sum_u \chi_u[n]a_{u,m}[n],
\qquad
\beta_{u,m}[n]=\frac{\chi_u[n]a_{u,m}[n]}{\max(1,N_m[n])}.
\]

实际上行速率为

\[
R_u[n]=\sum_m \beta_{u,m}[n]B_m
\eta_m^{\mathrm A}(\mathbf q_u[n]).
\]

缓存动态为

\[
Q_u[n+1]=\max\{0,Q_u[n]+A_u[n]-R_u[n]\Delta t\}.
\]

其中 \(A_u[n]\) 只在完成一个新巡检点时产生。缓存清空后，无人机立即退出上行带宽竞争；无数据无人机不能占用带宽或增加其他无人机的竞争人数。

### 5.6 G2A 可靠性

G2A 可靠性覆盖从物理起飞到任务完成的全部空中时间，包括空缓存飞行和到达区外等待，而不仅是上行活动时隙。无人机沿实际执行轨迹的累计期望中断时间为

\[
O_u=\sum_n\sum_m a_{u,m}[n]
p_m^{\mathrm G}(\mathbf q_u[n])\Delta t.
\]

定义空中任务时间

\[
T_u^{\mathrm{air}}=\sum_n b_u^{\mathrm{air}}[n]\Delta t.
\]

路线满足

\[
\frac{O_u}{T_u^{\mathrm{air}}}\le\epsilon_{\mathrm{out}}.
\]

地面起飞时移 \(\delta_u\) 计入系统 makespan，但不进入中断时间的分子或分母，因此不能通过延迟起飞稀释可靠性违规。

最大连续中断时间作为独立报告指标和扩展约束。若当前实现尚未稳定支持该约束，不把它写入首轮主结论。

### 5.7 系统指标

无人机 \(u\) 的完成时间 \(T_u\) 包括起飞时移、飞行、到达区外等待上传以及返回终点，且必须满足 \(T_u\le T_{\max}\)。系统 makespan 为

\[
T=\max_u T_u.
\]

数据包 \(k\) 从巡检完成到缓存中相应数据被完全传输的时间为 \(D_k\)，总上传完成时延为

\[
D=\sum_{k\in\mathcal K}D_k.
\]

主目标为

\[
\boxed{
J=\omega_T\frac{T}{T_{\mathrm{ref}}}
+\omega_D\frac{D}{D_{\mathrm{ref}}}
},
\qquad \omega_T+\omega_D=1.
\]

\(T_{\mathrm{ref}}\) 和 \(D_{\mathrm{ref}}\) 必须由预注册的同一基线生成，并在同一实验族内固定。所有单段门控表同时报告原始 \(T,D\)，不得用未归一化的 \((T+D)/2\) 冒充正式目标。

## 6. 时空冲突定义

两架无人机在时隙 \(n\) 构成有效扇区冲突，当且仅当二者都有待上传数据且关联同一扇区：

\[
C_{uv}[n]=\chi_u[n]\chi_v[n]
\mathbb I\{m_u[n]=m_v[n]\},\quad u\ne v.
\]

系统冲突强度可定义为

\[
H=\sum_n\sum_m
\left(N_m[n]-1\right)_+\Delta t.
\]

仅统计共扇区人数仍不足以描述损失，因此同步评价器还计算每个活动时隙相对独占带宽的速率损失：

\[
L_{mathrm{cong}}
=\sum_{u,n}\left(R_u^0[n]-R_u[n]\right)\Delta t.
\]

对具体航段 \(e\) 定义热点分数 \(H_e\)，累计该航段执行期间引起或遭受的速率损失。STC-ALNS 使用 \(H_e\) 选择破坏对象，而不是给一架无人机的所有边统一乘同一个平均因子。

## 7. STC-ALNS 求解方法

### 7.1 解表示

一个候选解表示为

\[
\mathcal S=
\{\mathcal R_u,\mathcal C_u,\delta_u\}_{u\in\mathcal U},
\]

其中：

- \(\mathcal R_u\) 是无人机 \(u\) 的巡检点顺序；
- \(\mathcal C_u\) 为路线中每条有向边选定的航段候选编号；
- \(\delta_u\in\mathcal D\) 为有界离散起飞时移。

任务分配由巡检点出现在哪条 \(\mathcal R_u\) 中隐式表示。每个点必须且只能出现一次。

### 7.2 可行性优先

候选解按以下字典序比较：

1. 未访问任务数；
2. 上传未完成次数；
3. G2A 中断约束违规量；
4. 其他硬约束违规量；
5. 正式目标 \(J\)。

不可行解不能仅凭较低飞行时间战胜可行解。允许在搜索早期使用带显式违规度的罚函数穿越不可行区域，但保存的 best feasible 必须独立维护。

### 7.3 Destroy 算子

- Random removal：随机移除若干任务；
- Worst-cost removal：移除边际目标贡献最大的任务；
- Critical-route removal：从当前 makespan 关键路线移除任务；
- Conflict-hotspot removal：优先移除 \(H_e\) 最大航段附近的任务；
- Sector-related removal：移除在相同扇区和相近时间造成拥塞的一组任务；
- Infeasibility removal：优先处理上传或中断约束违规附近的任务。

### 7.4 Repair 算子

- Cheapest feasible insertion；
- Regret-2/Regret-3 insertion；
- Makespan-balancing insertion；
- Conflict-aware insertion：使用局部同步评价得到插入后的边际拥塞代价；
- Sector-diversity insertion：在成本接近时优先选择扇区占用与其他无人机差异更大的航段候选。

### 7.5 局部搜索与资源动作

- relocate、swap、2-opt；
- path-switch：保持任务顺序，只切换某条边的候选航段；
- departure-shift：调整一架无人机的起飞时移；
- conflict-window shift：只对造成热点的路线执行小范围时移；
- route-tail exchange：交换两架无人机的路线尾部以消除长期扇区重叠。

### 7.6 自适应算子权重

算子 \(o\) 的选择概率由权重 \(w_o\) 决定。每个统计周期后，根据产生全局最优、改善当前解、被接受或被拒绝的结果累计得分 \(s_o\)，更新

\[
w_o\leftarrow(1-\rho)w_o
+\rho\frac{s_o}{\max(1,n_o)},
\]

其中 \(n_o\) 为该周期算子使用次数。这样方法才可严格称为 ALNS，而不是均匀随机多邻域搜索。

### 7.7 接受准则

可行性层级改善的候选直接接受；同一可行性层级中，若目标变差 \(\Delta J>0\)，按模拟退火概率

\[
P_{\mathrm{acc}}=\exp(-\Delta J/T_{mathrm{SA}})
\]

接受。温度、冷却率和停止条件必须在验证集上确定，并对所有正式测试场景固定。

### 7.8 增量同步评价

每架无人机缓存自身完整时间线：位置、航段、缓存、关联扇区、独占速率和中断概率。一次局部修改只重建受影响无人机从最早变化时刻开始的时间线，并重新计算与其扇区重叠的其他无人机窗口。周期性执行一次完整重放，检查增量值与全量值一致。

论文同时报告：

- 全量同步评价调用次数；
- 增量评价调用次数；
- 缓存命中率；
- 搜索墙钟时间；
- 增量评价相对全量重放的误差，应为数值容差内零误差。

## 8. 航段库生成

### 8.1 Comm-Waypoint

从起终点连线附近、局部 A2G 高频谱效率区和 G2A 低中断区生成候选中继点。候选路径可包含零个、一个或两个中继点。对每条路径执行统一动力学重放和上传仿真，并保留非支配候选。

候选点不能直接从测试结果中人工选择；网格分辨率、候选数量和筛选规则在验证集上固定。

### 8.2 Grid A*/Dijkstra

构建空间图，节点包含位置，边代价包含飞行时间、预计上传进度和 G2A 可靠性。图搜索只可称为“离散图上的最优解”，不得称为连续空间全局最优。

### 8.3 SLSQP 精化

以若干最优离散路径的中继点作为多起点，对连续中继位置进行局部优化。SLSQP 结果必须经过统一离散时隙评价器重放；若精化结果不可行，则保留原离散候选。

### 8.4 学习型代理的停止门槛

若开展旁支 TD3 重设计，只进行一次预注册门控。新策略至少需要：

- 显式观察局部 A2G 速率、G2A 中断、剩余数据和可用资源；
- 在多张训练地图上训练，在不参与调参的测试地图上评估；
- 在共同可行边集合上稳定优于 Straight-Hold；
- 相对 Comm-Waypoint 的目标差距足够小，同时在线推理速度显著更快。

若无法同时满足性能和速度价值，不再继续扩大 DRL 训练，TD3 仅作为负结果或普通基线。

## 9. 统一同步评价器

统一评价器是所有方法唯一的最终裁判，输入为路线、航段候选、起飞时移和场景，输出至少包括：

- 系统可行性及失败原因；
- makespan \(T\)；
- 总上传完成时延 \(D\)；
- 每架无人机路线级 G2A 中断比例；
- 最大连续中断；
- 扇区占用、活动上传者数量和冲突强度；
- 等待时间、飞行时间和上传完成时间分解；
- 运行时间。

每个时隙严格按以下顺序更新：

1. 激活到达起飞时移的无人机；
2. 根据选定航段推进位置；
3. 判断是否到达巡检边界外的等待点；
4. 为全部空中无人机进行上下行一致的扇区关联；
5. 根据当前缓存确定活动上传者并分配上行带宽；
6. 更新上传速率和缓存；
7. 缓存清空后完成最后连接段，在统一服务锚点触发下一巡检并生成新数据；
8. 更新 G2A 中断、延迟、完成时间和失败状态。

评价器必须具备以下守恒测试：

- 每个时隙每个扇区分配带宽不超过 \(B_m\)；
- 无数据无人机分配带宽为零；
- 所有空中无人机均有且只有一个 G2A 服务扇区，地面等待不累计 G2A 中断；
- 每个数据包上传量加剩余量等于生成量；
- 不允许在上一数据未清空时完成下一巡检；
- 连续航段在同一服务锚点拼接，不出现位置跳变；
- 超过 \(W_{\max}\) 或 \(T_{\max}\) 的解确定性地判为失败；
- 单无人机情况下同步评价应退化为独占带宽评价；
- 无扇区重叠情况下，多无人机结果应等于各单机时间线并集；
- 增量评价与全量评价结果一致。

## 10. 复杂度与小规模精确基准

联合问题至少包含多旅行商/车辆路径子问题，因此为 NP-hard。论文应给出从多旅行商或广义车辆路径问题到本问题受限特例的简洁归约，而不是仅以“变量很多”声称困难。

对 \(U\le2\)、\(K\le8\)、每边候选数受限的小规模实例，建立时间离散的枚举、动态规划、CP-SAT 或 MILP 基准，得到精确最优或可验证下界。报告：

- STC-ALNS 的可行率；
- 相对最优解或下界的 gap；
- 求解时间；
- 随规模增长的精确求解失效点。

精确基准只需覆盖离散候选空间，不宣称代表连续空间全局最优。

## 11. 实验设计

### 11.1 RQ1：通信感知航段是否有价值

固定同一地图、边集合、数据量和评价器，比较 Straight-MaxSpeed、Straight-Hold、Comm-Waypoint、Grid A*/Dijkstra、SLSQP、TD3、DDPG、SAC。报告：

- 全边可行率；
- 共同可行边集合上的配对 \(T,D,O\)；
- 失败原因分布；
- 航段生成或推理时间；
- 候选库规模和 Pareto 多样性。

Straight-MaxSpeed 仅作飞行时间松弛参考，不参与可行方法排名。

### 11.2 RQ2：时空冲突模型是否必要

对同一组路线比较：

- 独占带宽评价；
- 静态平均拥塞因子；
- 精确同步评价。

报告静态近似对 \(T,D\) 和可行性的误差，并展示至少一个静态边权排序被同步评价反转的案例。

### 11.3 RQ3：STC-ALNS 是否优于普通路线搜索

统一使用相同航段库和同步评价器，比较：

- nearest-neighbor + 2-opt；
- cheapest insertion + local search；
- 普通 LNS-SA；
- 仅使用静态拥塞因子的迭代 LNS；
- STC-ALNS；
- 小规模精确解。

报告系统成功率、\(T,D,J,O,H\)、墙钟时间和最优性 gap。

### 11.4 RQ4：哪项机制产生收益

至少包括：

- 无 conflict-hotspot destroy；
- 无 conflict-aware repair；
- 无 path-switch；
- 无 departure-shift；
- 固定算子权重；
- 单候选边表；
- 全量评价与增量评价时间比较。

每次只移除一项，其余设置保持不变。

### 11.5 RQ5：规模与鲁棒性

实验分开设计，禁止混杂解释：

1. **UAV 数量实验**：固定区域、基站、巡检点和数据，只改变 \(U\)；
2. **任务规模实验**：固定点密度和基站密度，改变区域与 \(K\)；
3. **通信负载实验**：改变数据量、带宽和固定发射功率；
4. **地图鲁棒性实验**：独立 `map_seed`，训练/验证/测试严格隔离；
5. **快衰落鲁棒性实验**：在规划地图上求解，在独立信道样本上蒙特卡洛重放。

### 11.6 随机种子和统计

明确区分：

- `map_seed`：地形、建筑和无线图；
- `task_seed`：巡检点和数据量；
- `method_seed`：ALNS/启发式搜索随机性；
- `train_seed`：仅用于学习型基线。

主方法与基线在相同场景实例上配对。至少使用 5 个独立场景实例，每个实例运行多个 method seed；学习方法还需要多个 train seed。主要结果报告：

- 均值、中位数、标准差和 95% 置信区间；
- 配对差值及其 95% 置信区间；
- 配对置换检验或 Wilcoxon 检验；
- 多重比较时使用 Holm 校正；
- 同时报告效应量，不能只报告 p 值。

## 12. 论文结论闸门

只有满足对应闸门，论文中才能使用相应结论：

### Gate 0：评价器可信

所有带宽、缓存、任务语义和增量一致性测试通过；人工构造小例能够手算复现。

### Gate 1：航段层成立

至少一种通信感知优化航段在共同测试集合上相对 Straight-Hold 取得稳定的通信或综合目标改善，且没有通过放宽可行性获得优势。

### Gate 2：冲突反馈成立

STC-ALNS 相对普通 LNS-SA 和静态拥塞反馈方法，在同步评价器下取得跨场景一致改善，配对置信区间不跨零；若只改善可行率，则论文必须以可靠可行为主结论，而不能声称降低目标。

### Gate 3：算法创新成立

冲突 destroy/repair、航段切换、自适应权重或起飞时移至少有两项在消融中产生可重复贡献；小规模最优性 gap 和中等规模时间均可接受。

### Gate 4：证据可复现

正式表图全部来自冻结 run，manifest 完整，且不存在跨地图、跨 checkpoint 或跨代码版本拼接。

若 Gate 2 或 Gate 3 不通过，不应继续以 TVT 为目标包装现有结果，应回到算法设计阶段。

## 13. 结果冻结规范

每次正式 run 使用独立不可覆盖目录，保存：

- Git commit、dirty diff 和仓库状态；
- Python、NumPy、SciPy、PyTorch 等依赖版本；
- 全部配置、巡检点、数据量和四类 seed；
- A2G/G2A 地图代码、地图参数和原始栅格 hash；
- 候选航段库、模型 checkpoint、路线、时间线和日志；
- 完整命令行、开始/结束时间和退出状态；
- 原始指标 JSON/NPZ 与绘图脚本；
- SHA-256 manifest。

图片不能作为唯一结果来源；所有表图必须由冻结的机器可读原始数据重新生成。

- `radio_map/`：在单位和地图 seed 接口进一步统一后复用；
- `segment/env.py`：复用单段运动、上传和中断查询逻辑，但不再作为最终多机裁判；

- 现有 TD3/DDPG/SAC：保留为学习型基线；
- 现有 Comm-Waypoint/Straight-Hold：作为航段库生成器起点。

### 14.2 必须重构

- 将平均每机 `delay_factor` 改为具体边—时间窗口的同步边际代价；
- 评价器只让缓存非空的无人机参与带宽竞争；
- 所有补传等待发生在下一巡检点到达区之外；
- 航段库从“一条边一个结果”扩展为“一条边多个 Pareto 候选”；
- ALNS 增加自适应权重、冲突算子、path-switch 和 departure-shift；
- 多 seed 代码区分场景、地图、方法和训练随机性；
- 结果文件改为 run-scoped，不再覆盖共享文件名。

### 14.3 暂缓

- N=4 TD3 专门调参；
- 端到端 MARL 大规模复训；
- 将能量、安全投影和动态任务同时加入主问题；
- 在统一评价器完成前继续生成正式论文结果。

## 15. 主要风险及应对

### 风险 1：同步评价过慢

采用时间线缓存、受影响窗口增量更新和周期性全量校验。若仍过慢，可训练代价代理用于筛选，但最终候选必须经精确同步评价。

### 风险 2：STC-ALNS 收益仍然很小

先构造具有可控扇区重叠的压力场景验证机制，再在自然场景上报告真实收益。不得只选择有利场景；若自然场景冲突本来很少，应诚实说明资源协调价值受负载条件限制。

### 风险 3：航段优化收益依赖功率

固定主场景物理参数来源，并对功率、带宽和数据量进行预注册敏感性分析。不同功率下重新生成航段库；不能把固定策略的分布外测试解释为算法本身的稳健收益。

### 风险 4：方法组合看起来只是工程堆叠

论文必须围绕一个统一概念展开：时空扇区冲突。航段库提供可替换的冲突签名，STC-ALNS 用冲突信息搜索，同步评价器给出真实反馈。所有模块都服务于同一问题，而不是分别声称独立贡献。

## 16. 批准后的下一步

本设计获批后，下一步不是直接训练或跑大规模实验，而是编写分阶段实施计划。建议阶段顺序为：

1. 冻结当前结果并建立新 run 目录规范；
2. 定义统一数据结构和同步评价器测试；
3. 完成航段候选库；
4. 实现冲突指标与全量/增量评价；
5. 实现 STC-ALNS 算子和自适应权重；
6. 完成小规模精确基准；
7. 通过 Gate 0–3 的小规模门控；
8. 执行正式多场景实验并冻结论文结果。
